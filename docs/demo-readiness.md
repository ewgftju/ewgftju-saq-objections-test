# Сценарий показа заказчику

Сайт: https://saq-objections-test.vercel.app/

## Перед показом

Открыть реестр и при необходимости нажать «Сбросить демо». Все три дела должны иметь статус «Поступило». Роль по умолчанию — «Рабочий орган», дата — 08.09.2026. Не вводить реальные персональные и служебные данные в тестовые обращения.

## Что показать

| Шаг | Дело | Результат показа |
|---|---|---|
| 1 | ВОЗ-2026-001: уведомление | Приём → позиция ДВГА → анализ двух спорных пунктов → комиссия → протокол → заключение. Пункт 3 не оспорен и сохраняется. |
| 2 | ВОЗ-2026-002: аудиторский отчёт | Частичное удовлетворение, учёт суммы и третьих лиц, заслушивание, решение по пунктам. |
| 3 | ЖАЛ-2026-003: акт профконтроля | Проверка компетенции → передача дела → полный анализ → заслушивание обеих сторон → решение вышестоящего органа. |
| 4 | Любое завершённое рассмотрение | Просмотр и печать результата; отдельная фиксация вручения; регистрация судебного обжалования. |
| 5 | Любое незавершённое специальное возражение | Дополнение, приостановление по внешнему запросу, пересчёт сроков и неизменяемые снимки сформированных документов. |

Следующее действие и ответственный показаны справа. Для продолжения переключить роль в шапке или кнопкой в карточке. При заслушивании выбрать дату не менее чем через 3 рабочих дня после извещения. В голосовании есть явная кнопка заполнения тестовых голосов «За». Остальные значения и отметки вводит демонстратор.

## Что согласовать с ДВГА

1. Компетентный орган и специальный порядок жалобы для конкретного вида профилактического контроля и категории субъекта.
2. Состав участников, распределение ответственности и утверждённые формы документов.
3. Формулировки решений и последствия по исходным пунктам, включая передачу результата в модуль-источник.
4. Актуальные официальные редакции НПА и производственный календарь для рабочего расчёта сроков.

## Что уже проверено

Строгая проверка TypeScript, production-сборка Vite и восемь автоматических проверок: три сквозных процесса, сроки, кворум/отводы/голоса, запрет недопустимых действий, продление и приостановление, сохранение и экранирование данных. React-разметка проверена серверным рендерингом; визуальная приёмка в реальном браузере и реальная доставка во внешние системы этими проверками не охватываются.

## После согласования макета

Серверные модели и API Django/DRF, настоящая авторизация, PostgreSQL, файловое хранилище, ЭЦП, СЭД/портал, события вручения, интеграция с исходными модулями, промышленный календарь и аудит операций. Для демонстрации тестовых сценариев эти интеграции не требуются.
